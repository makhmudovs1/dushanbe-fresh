# MVP

Строгие границы первого MVP для сервиса доставки свежих продуктов с рынков
Душанбе. Этот документ определяет, что делаем в первой версии, а что явно
откладываем.

## Реализованный операционный цикл

Заказ клиента → автоматический статус confirmed после серверной проверки → одна волна
на окно → агрегированный список с предпочтениями по качеству → закупка на рынке
→ «Упаковать заказы» → сборщик завершает сборку → курьер забирает → доставка
→ отметка получения наличных.

Первый confirmed-заказ автоматически создаёт волну своего слота и получает
дежурных сборщика и курьера из настроек. Следующие заказы открытой волны
добавляются автоматически. Обычный цикл не требует участия администратора:
курьер видит «Готовится», затем готовую партию и сам нажимает «Забрал заказы».
Администратор сохраняет контроль, переназначения и отмену неоплаченных заказов до доставки.
У сборщика три вкладки: «Предстоящие» (open), «В работе» (picking),
«Завершённые» (picked/out_for_delivery/delivered/cancelled).
Отклонение закупочной цены выше настраиваемого порога (по умолчанию 15%) отмечается
для проверки, но не блокирует сборку. Сборщик не может изменять цену клиенту.

Операционные страницы: `/admin/orders`, `/admin/orders/:id`,
`/admin/delivery-waves`, `/admin/delivery-waves/:id`. Сборщик и курьер назначаются
из пользователей соответствующих ролей. Отдельное приложение им не требуется.
Сотрудники входят по электронной почте и паролю. JWT-токен доступа живёт 10 минут,
токен продления обновляется при использовании и хранится в БД только как хеш SHA-256;
браузер получает его через httpOnly cookie с `SameSite=Lax` (`Secure` в боевом окружении).
Администратор управляет каталогом, заказами и назначениями; сборщик видит только назначенные волны и
вносит закупку/фактические количества; курьер видит только назначенные доставки
без закупочных цен и может отмечать доставку и наличные.

Стоимость закупки отделена от цены клиенту. Итоги закупки и заказов считает
сервер через Decimal. Показатель «Валовая маржа по товарам» исключает доставку,
сервисные сборы и операционные расходы и не является чистой прибылью.

Упаковка обычного заказа выполняется кнопкой «Всё упаковано как заказано»:
finalQuantity = requestedQuantity, цена берётся из сохранённой копии данных заказа.
Ручной ввод нужен только для исключений через «Изменить»;
сохранённые исключения не перезаписываются.
Закупленный излишек не распределяется клиентам: остаток = куплено минус фактически
упаковано по активным заказам. Это информационный показатель, не складской учёт.

## A. Возможности клиента

- Каталог товаров.
- Категории товаров.
- Карточка товара.
- Адаптивный веб-интерфейс для телефонов и компьютеров.
- Корзина.
- Выбор предпочтения по качеству для товаров, где это применимо.
- Политика замены для заказа:
  - заменить похожим;
  - связаться со мной;
  - удалить товар.
- Оформление без регистрации и обязательного одноразового кода по SMS.
- Имя, телефон и адрес доставки при оформлении.
- Сохранение копии адреса в заказе на момент оформления.
- Выбор 2-часового окна доставки.
- Создание заказа.
- Базовый статус заказа.
- История заказов, если она не усложняет MVP существенно.

## B. Возможности администратора

- Управление категориями.
- Управление товарами.
- Управление продажной ценой.
- Изменение доступности товара на сегодня.
- Изменение текущей закупочной цены, если она используется.
- Управление окнами доставки.
- Просмотр заказов.
- Изменение статусов заказа.
- Назначение сборщика.
- Назначение курьера.
- Сборочный лист по волне доставки.
- Просмотр агрегированных товаров по волне доставки.
- Ввод финального количества товара в заказе.
- Ввод фактической закупочной цены по товару в волне доставки.
- Ввод реально купленного количества по товару в волне доставки.
- Замена товара.
- Удаление отсутствующего товара из заказа.
- Изменение статуса оплаты.
- Базовые метрики дня:
  - заказы за день;
  - заказы по статусам;
  - сумма заказов;
  - загрузка окон доставки.

## C. Не входит в MVP

- Онлайн-оплата.
- Отслеживание курьера в реальном времени.
- Автоматическая оптимизация маршрутов.
- Оптимизация работы сразу с несколькими рынками.
- Складская система.
- Склад-магазин без обслуживания покупателей.
- Нативное мобильное приложение.
- Искусственный интеллект.
- Торговая площадка для сторонних продавцов.
- Программа лояльности.
- Промокоды.
- Мясо.
- Заморозка.
- Сложная холодовая цепь.
- Микросервисы.
- Redis, пока не появится реальная необходимость.
