# Корзина, Checkout И Заказы

1 ноября 2026. **Опубликовано на TARENA в 17:37 МСК.**
Область изменений: только покупательские корзина, оформление,
история и подробности заказа. NestJS, схема PostgreSQL, Payom и контракты API
не изменяются. Новых зависимостей нет.

## Компоновка

- Корзина: компактные строки с фотографией, разновидностью, количеством,
  ценой, степпером и удалением. Прогресс минимальной суммы над товарами.
  Справа отдельное «Итого», ниже рекомендации. На телефоне прежняя fixed-кнопка
  над навигацией, без новых viewport/scroll-lock механизмов.
- Checkout: адрес, контакты, окно доставки, замены; компактные поля адреса.
  Справа «Итого» с серверными суммами и кнопкой «Подтвердить заказ».
  Список справа показывается только для позиций с предупреждениями/ошибками.
  Checkbox проверки, reviewToken, requestId, валидация и отправка сохранены.
- История: крупная дата/время Душанбе, статус, сумма, адрес и до пяти миниатюр.
  Полная карточка открывает прежнюю приватную страницу отслеживания.
- Подробности: реальные снимки количества/стоимости, адрес, статус,
  финансовая разбивка, корректировки, повторные доставки и контакты поддержки.
  «Повторить» вызывает существующий защищённый метод и прежний repeatProducts;
  недоступные/legacy-позиции не заменяются молча. Повтор не создаёт заказ.
- Локальные стили `commerce.css`, шрифты 400/500/600/700/800, белый фон,
  чёрные основные кнопки, зелёный прогресс и небольшие статусные акценты.
  RU/TJ, desktop 1440 и mobile 375/390.

## Источники Данных И Ограничения

1. Cart pricing использует существующие GET delivery-slots и POST
   checkout/validate. Выбор первого доступного окна нужен только для preview,
   не сохраняется как выбор клиента. Checkout заново проверяет выбранное окно,
   адрес, цены и доступность. Суммы/минимум/остаток до минимума только серверные;
   debounce 300 ms, AbortController и ключ входных данных исключают stale quote.
   Ошибка preview не удаляет корзину и не блокирует переход к checkout.
2. Отдельного порога бесплатной доставки в текущем серверном расчёте нет.
   Не показываем выдуманную бесплатную доставку. Если нет окна или API недоступен,
   не придумываем доставку/минимум: сумма к оплате — прочерк до проверки.
3. API истории не содержит адреса и изображений. Карточки лениво запрашивают
   существующий customer/orders/:id только около видимой области. Ошибка этого
   необязательного запроса не скрывает сводку и ссылку.
4. PublicOrderLine не содержит Product.id или исторического фото. Используется
   только единственное точное совпадение русского snapshot-названия в текущем
   каталоге; переименованный, удалённый или неоднозначный товар получает нейтральную
   иконку. Это текущее фото, не обещание исторического снимка. Цены/вес берутся
   исключительно из заказа, а не из каталога.
5. Дата создания и ID для повтора берутся из авторизованной истории. При открытии
   старой карточки используется accountOrder как указатель для поиска в её
   пагинации, не как разрешение: принадлежность проверяется прежним API.
   Чужая/гостевая ссылка не получает повтор через чужой аккаунт. Без доступной
   даты показываем номер заказа, не выдуманную дату. Без владельца — переход
   в «Мои заказы», без обхода SMS/claim.
6. Адрес показывает все поля существующего публичного DTO: город, улица, дом,
   квартира, подъезд, этаж. Домофон/комментарии, не выдаваемые этим API, не
   извлекаются обходными путями. Поддержка ведёт на существующую страницу /about
   с контактами; данных курьера, чеков или онлайн-оплаты не придумываем.

## Релиз

Подготовлен Web-only rollout `ops/tarena/deploy-commerce-web.py`. Образ собирается
вне VPS из Git archive. Существующий API 4013, БД, секреты и SMS-ledger не меняются.
Кандидат Web на loopback 3002 прогревается; Caddy меняет только Web upstream
graceful reload, после проверки новой сборки прежний Web 3001 останавливается.
При ошибке переключения routing возвращается на прежний Web TARENA, не Алматы.
Новая точка управления Web: state/commerce-current.json; API остаётся под
исходным compose, запускать в нём только api, не восстанавливать старый web.

Ревизия приложения: `600e648fa5ee90e1bf93affd246f6a1afd97074b`.
Образ Web: `df-tarena-web-commerce:600e648fa5ee`; слои, runtime-конфигурация,
Git label и checksum helper сверены после передачи. Доверенный исходный код —
Git archive, никакие локальные ENV или старые исполняемые файлы не копировались.

Receipt: `/srv/dushanbe-fresh/state/releases/commerce-600e648fa5ee/result.json`.
Активный Web: `df-commerce-web-600e648fa5ee`, loopback 3002, лимит 384 MiB.
API остался `df-auth-ux-api-06feacb81ca4` на 4013; API/PostgreSQL/Caddy не
перезапускались. Миграции не выполнялись. Прежний Web TARENA остановлен после
прогрева и успешной проверки нового публичного build manifest.
Root ENV и израсходованные SMS-ledger/recipient/grant сохранились без изменений.
DNS/SSH/firewall и Алматы не затрагивались. Новых SMS/реальных заказов при релизе нет.
Проверенная резервная копия — snapshot
`bbfc16aa8ad0cb14d16a1ef46241b93de9a3c290896bb44ccffbb1ddc9b522c4`;
внешним независимым хранилищем она не является.

Дополнительно проверены два теста безопасного изменения Caddy bind-файла
(сохранение inode/permissions, отказ от symlink/hardlink).
