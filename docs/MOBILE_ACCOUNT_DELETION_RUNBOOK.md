# Удаление аккаунта Dushanbe Fresh

Запрос доступен в **Профиль → Настройки → Удалить аккаунт** и на внешней WEB-странице `/account/delete`. Оба пути подтверждают текущий аккаунт и актуальную версию двуязычных условий. При принятии запроса сервер отзывает WEB и MOBILE сессии и действующие коды входа владельца. Клиент получает идентификатор запроса. Любое повторное исполнение завершённого запроса возвращает ту же квитанцию.

## Перед включением

1. Владелец продукта и ответственный за данные утверждают назначение и срок хранения для каждой категории, правила доступа и резервных копий, обработку спорных случаев, сроки и канал ответа клиенту. Черновик для согласования лежит в [материалах для магазинов](MOBILE_STORE_MATERIALS_RU_TJ.md).
2. В изолированном стенде проверьте оба входа, запрос, завершение и обработку активного заказа. После deployment проверьте доступность внешней страницы, условия RU/TJ и отображение в приложении. Для включения приёма используются `CUSTOMER_ACCOUNT_DELETION_REQUESTS_ENABLED=true`, `CUSTOMER_ACCOUNT_DELETION_POLICY_VERSION`, `CUSTOMER_ACCOUNT_DELETION_NOTICE_RU`, `CUSTOMER_ACCOUNT_DELETION_NOTICE_TG` и серверный ключ квот.
3. Назначьте ограниченную группу операторов с доступом к закрытой очереди и CLI. До внешней активации согласуйте выполнение запросов с удержанием данных, запросы после смены номера и порядок обработки после восстановления резервной копии. Сопоставляйте внутреннее дело с `requestId`; адреса, номера и коды входа храните вне журнала CLI.

## Исполнение подтверждённого дела

Команда работает с явно заданным `DATABASE_URL`. Для репетиции используйте отдельную синтетическую PostgreSQL. В вашем закрытом окружении оператора БД должны быть настроены и проверены заранее.

```sh
corepack pnpm --filter @dushanbe-fresh/api exec tsx src/scripts/process-account-deletion.ts "$DF_DELETE_REQUEST" "$DF_DELETE_POLICY"
```

Команда возвращает количество связанных заказов, коды ограничений и отпечаток текущего объёма. При наличии ограничения передайте дело ответственному за данные. Программа приостанавливает дела с активными заказами, несведённой кассой, инцидентами, сложными финансовыми корректировками, неоднозначным владением заказом или дополнительными записями аудита. Требование сохранить конкретные персональные поля по утверждённой политике также означает ручное рассмотрение дела до запуска CLI.

Когда ответственное лицо подтвердило допустимость удаления по показанной версии политики и пустой список ограничений, выполните команду в том же операторском окружении. `CUSTOMER_ACCOUNT_DELETION_POLICY_VERSION` должен совпадать с проверенной версией записи.

```sh
CUSTOMER_ACCOUNT_DELETION_EXECUTION_ENABLED=true \
  corepack pnpm --filter @dushanbe-fresh/api exec tsx src/scripts/process-account-deletion.ts \
  "$DF_DELETE_REQUEST" "$DF_DELETE_POLICY" --apply "$DF_DELETE_REVIEWED_FINGERPRINT"
```

При изменении данных сформируйте и согласуйте новый план. Транзакция удаляет профиль, связанный клиентский профиль, одноразовые коды, сохранённые адреса, корзину, избранное и токены. Она очищает контакты, координаты, примечания и связи с субъектом на подходящих заказах, отзывает старые ссылки отслеживания и сохраняет номер заказа, даты, статусы, позиции, количества, суммы и кассовые операции. Идентификатор запроса checkout остаётся зарезервирован для защиты от повторной отправки. Сохраняется квитанция удаления без ссылки на пользователя.

Проверьте статус `completed` перед уведомлением по утверждённому каналу. Удаление из живой БД требует согласованного цикла для копий, логов, провайдеров и отдельного рассмотрения ограниченных дел. Протокол согласования оператора должен действовать к моменту включения внешнего запроса.
