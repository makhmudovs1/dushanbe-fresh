# Выбор Адреса

## Компоновка

- Desktop: окно шириной до 940px, единый поиск над большой картой и нижняя
  чёрная кнопка. Подсказки накладываются на карту, не открывают новый экран.
- Mobile: высокий sheet (95% visual viewport), крупная карта, фиксированный
  в структуре footer с safe-area. Поиск не открывает клавиатуру автоматически.
- В отличие от старого flow нет экранов выбора центра/применения reverse,
  технической надписи о подключении и конкурирующих основных команд.
- Форма деталей повторяет структуру референса: Дом/Работа/Другое, улица/дом,
  квартира/дом, реквизиты входа и комментарий. Одна кнопка сохранения.
- Сохранённые адреса: список с отдельным редактированием и добавлением.
  Header, профиль и checkout используют один picker и прежние модели адресов.

Сравнены настоящие тайлы `positron` и `osm-bright` одного участка Душанбе.
Выбран `positron`: светлая нейтральная подложка не конкурирует с адресом и меткой.
Визуально проверены desktop/mobile screenshots: композиция соответствует
референсам поиска/карты, списка и компактных деталей; жёлтый заменён графитовым.
Ошибки локального каталога на фоне не скрывались декоративными заглушками.

## Координаты И Ошибки

Центральная брендовая метка неподвижна, перетаскивается карта. После остановки
reverse заполняет улицу/дом, не заменяя точную выбранную точку центроидом улицы.
Ручное уточнение дома сохраняет координаты. Поздний reverse, поиск или GPS не
перезаписывает новый пользовательский ввод. Изменение viewport не считается
ручным перемещением карты. GPS запрашивается только кнопкой.

Пустые/ошибочные ответы допускают ручной ввод, частный дом не требует квартиры.
Поиск/карта соблюдают существующую рамку Душанбе; серверные checkout-проверки
не менялись. Координаты и навигация курьера используют существующий order snapshot.
Никаких реальных заказов и SMS тесты не создают.

## Проверки

- Workspace lint/typecheck и изолированная сборка прошли. 535 unit-тестов:
  shared 6, Web 306, API 223.
- Chromium и WebKit: по 15 address/courier browser-сценариев, RU/TJ,
  375/390/1440px; высота 620px, landscape 844x390, возврат к portrait.
- Настоящие Geoapify-тайлы; в regression-тестах geocoder/API аккаунта изолированы
  моками. Поиск, pan, pin, ручной дом, сохранение/reload, PATCH старого id,
  пустой ответ/503, отказ и запоздалый GPS, reverse failure, устаревшие подсказки,
  точка вне города, курьерские координаты и навигация.
- Дополнительно настоящий Geoapify в WebKit: mobile RU / desktop TJ,
  Autocomplete + Reverse, ручное уточнение и сохранение точных координат.
  Оба языка вернули по 3 настоящие уличные подсказки; совпадающие по имени POI
  исключены. Ключи отдельно проверены с production IP/origin: оба ответа 200.
- Проверка private key в DOM, browser requests, JSON и клиентской сборке;
  публичный ключ тайлов намеренно доступен. ENV игнорируется Git.

Артефакты regression: `/private/tmp/df-picker-20261026/{chromium-final,webkit-final}`.
Настоящий поиск: `test-results/address-picker-live-20261026/` (Git ignored).
Это WebKit, не физический iPhone: реальная клавиатура и динамические панели
Safari требуют дополнительной проверки на устройстве.

127 DB-dependent unit/integration-тестов пропускаются без выделенной тестовой БД;
производственная БД для них не используется. Существующие сценарии account UI
обновлены под новый picker, но их реальный DB/OTP-прогон отдельно не выполнялся.
Локальная ошибка каталога диагностирована [отдельно](LOCAL_CATALOG_500_20261026.md).

## Границы Релиза

После отдельного сообщения владельца разрешены Git push и production rollout.
Релиз только Web: API runtime, миграции и данные не меняются, SMS/обязательная
авторизация не включаются. Перед активацией требуется отдельное разрешение на
перенос локальных Geoapify-ключей в закрытый production ENV. Владелец отдельно
подтвердил перенос обоих ключей. Реальные значения не входят в Git, команды,
документацию или отчёты.
