# Главная и покупка без выбора качества

## Изменения

- Большой баннер овощей слева, два меньших справа: фрукты и молочные продукты.
  На планшете большой баннер сверху, два меньших рядом под ним; на телефоне
  все три идут вертикально. Текст и кнопки — HTML с RU/TJ, не часть изображения.
- Под ними — доставка по Душанбе, свежие продукты, бережная сборка. Без обещания
  сроков, скидок, происхождения или наличия, не подтверждённых данными.
- Тематические разделы идут строго сверху вниз. Порядок/названия/видимость и
  наличие берутся из каталога, последними идут до 8 товаров и «Все продукты».
- Категория: breadcrumbs, затем h1, затем общий двухколоночный блок с реальным
  деревом категорий слева и товарами справа. Единственный поиск остаётся в хедере.
- В каждой карточке одинаковый белый круглый плюс на фото; после добавления
  на том же месте появляется счётчик. Фото, галерея, настоящие priceDrop,
  избранное, минимальные количества и шаги сохранены.
- Убраны quality selectors в сетке и на странице товара. Новые покупки передают
  явный `qualityOptionId: null`, без скрытого выбора «спелый»/первого варианта.
- Уже сохранённые позиции корзины не мигрируются, не объединяются и не теряют
  прежние предпочтения. Карточка показывает их суммарное количество; +/- меняют
  существующую строку, удаляя её при достижении минимума по прежнему правилу.
  В корзине старые позиции и в истории заказов старые snapshots остаются точными.
- Hover/active корзины больше не получают тёмную заливку из старого `!important`.
  Устранён конфликт специфичности display/padding; значок центрирован, размеры
  стабильны, счётчик не накладывается, доступен keyboard focus.

## Категории и безопасность

Кнопки баннеров ведут только в существующие видимые непустые категории.
Если молочная категория отсутствует/скрыта/пуста, её баннер показывает
«Скоро в магазине» без ссылки. Пустой тематический раздел не создаётся.
Возвращать удалённую категорию, создавать «Самый сезон» или подкатегории
из названий товаров автоматически не требуется и не выполняется.

Без изменений backend, Prisma schema, API contracts, цен, закупочных ориентиров,
наценки, checkout calculations, авторизации и operational flow. Новых миграций нет.
Для production используется прежний процесс: backup PostgreSQL, сборка отдельно
от работающего приложения, замена `.next` с сохранением старых static chunks и
rollback-сборки, перезапуск только Web. API не требует перезапуска.
