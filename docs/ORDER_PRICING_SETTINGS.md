# Настройки стоимости заказа

## Интерфейс

`/admin/settings`, раздел «Условия заказа»:

- Минимальная сумма заказа, сомони.
- Стоимость доставки, сомони.
- Сервисный сбор, сомони.

Все три поля обязательны. Отсутствующие значения остаются пустыми, без
автоматического создания production-тарифов. Допустимы ноль и неотрицательные
суммы с максимум двумя знаками после точки/запятой. Ошибка сохранения остаётся
видимой; успешное сохранение подтверждается и значения перечитываются с API.

Если ранее включён `service_fee_percent > 0`, форма показывает действующую
процентную ставку. Как и прежде, фиксированный сбор используется при ставке 0%.
Ни ставка, ни другие настройки при сохранении этих трёх сумм не меняются.

## API и безопасность

`PATCH /api/v1/admin/settings/order-pricing`, только существующая роль admin:

```json
{
  "minimumOrderAmount": "150.00",
  "deliveryFee": "15.00",
  "serviceFee": "0.00"
}
```

Пример не является production-настройкой. API принимает десятичные строки,
проверяет все значения до записи и сохраняет три ключа `app_settings`
транзакционно с двумя знаками после точки. Текущая роль повторно проверяется
в транзакции. Событие `settings.order_pricing_changed` идёт в operational audit.
Схема Prisma, checkout calculations, цены товаров и snapshots старых заказов
не меняются. Миграций нет, существующие строки не удаляются.

- HTTP integration: 401 для гостя, 403 для picker/courier, проверка пропущенных,
  отрицательных, слишком больших и дробных сумм; отсутствие частичных записей;
  создание отсутствующих ключей, обновление без дублей, нулевые значения, audit.
- Пять component tests: загрузка, пустые настройки, существующие суммы,
  блокировка формы, действующая процентная политика.

  успешное сохранение, перезагрузка, 375/768/1440 px без переполнения.
