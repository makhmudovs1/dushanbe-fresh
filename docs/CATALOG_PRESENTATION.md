# Карточки, Галерея И Цена

Изменение от 2026-10-13 касается карточек каталога, галереи товара и секций фото/
истории цены в admin. Header, footer, категории, checkout и operational flow не
переделываются. Компоновка следует приложенному reference, бренд остаётся своим.

## Карточки

Квадратное фото с компактной availability, точки только для нескольких фото,
цена, строка единицы цены, название до двух строк, широкий выбор/stepper.
Зелёная кнопка «Выбрать» с Lucide ShoppingBasket занимает ширину карточки.
Название занимает две строки, media и loading controls имеют стабильные размеры.
Строка `1 кг` / `1 пучок` — именно единица продажной цены, не выдуманная фасовка.
Начальный выбор сохраняет прежнее minQuantity/quantityStep. Для basil/mint
остаётся пояснение `(~7 веточек)` / `(~7 шохча)`. Trend идёт рядом с единицей
и появляется только при реальном снижении. Описания не выводятся в grid,
но сохраняются в БД/API и на странице товара на RU/TJ. Новые обложки из архива
владельца и прежние фото/лицензии: [PRODUCT_IMAGES.md](PRODUCT_IMAGES.md).

## Галерея

`ProductImage`: id, productId, url, sortOrder, isPrimary, createdAt, updatedAt.
`Product.imageUrl` сохраняется и синхронизируется с обложкой при сохранении admin.
API добавляет `images[]`: сначала обложка, затем остальные по sortOrder.
При отсутствии галереи используется прежний image, затем брендовый placeholder.

Admin загружает до 12 JPEG/PNG/WebP по 5 МБ через прежний MediaService. Фото можно
удалять из галереи, назначать главным, менять порядок стрелками или drag-and-drop.
Удаление обложки выбирает следующий кадр; удаление всех оставляет placeholder.
Физические файлы не удаляются автоматически: возможные ссылки старых корзин и
лицензионной страницы не ломаются. Несохранённые загрузки могут оставить файлы без
связи с товаром; автоматическая очистка хранилища в эту задачу не входит.
Старая форма admin с одним полем image не удаляет галерею при неизменной обложке.
Если она заменяет/удаляет обложку, остальные фотографии сохраняются; новую галерею
целиком задаёт только явное поле images[].

## История Цен

`ProductPriceHistory` хранит старую/новую продажную цену Decimal(12,2), время,
productId и nullable changedByUserId. Admin PATCH блокирует строку товара;
изменение цены и новая запись истории сохраняются в одной транзакции. Одинаковое
числовое значение (`9.20` и `9.2`) не создаёт запись. Создание товара тоже не
создаёт скидку. Закупочные цены никогда не участвуют в истории продажной цены.

Публичный DTO добавляет `priceDrop` только если последнее изменение снизило
текущую продажную цену. `discountPercent = (old - new) / old × 100`, вычисляется
Decimal и округляется HALF_UP до целого. Рост цены убирает скидку. Старый процент
не сохраняется после следующего изменения. Срок акции не вводится.

## Миграция

`20261013160000_catalog_gallery_prices` создаёт только две новые таблицы, индексы
и FK; частичный unique index не допускает две обложки. INSERT копирует прежние
непустые imageUrl, включая soft-deleted товары, не изменяя Product. История цены
остаётся пустой: пилотные цены не превращаются в фиктивные акции.

Миграцию сначала проверяют на отдельной локальной БД. В production сначала
custom-format backup PostgreSQL и проверка `pg_restore --list`, snapshot
существующих таблиц/цен, затем `pnpm db:deploy` с существующим production env.
`pnpm db:backfill:images` позволяет безопасно повторить backfill: уже заполненные
галереи не затрагиваются. После deploy сравниваются Product и остальные прежние
таблицы, проверяются галерея/public DTO и отсутствие price history. Не запускать
seed, import-pilot, reset или restore в рамках этого обновления.

## Проверки

Unit: порядок/обложка/fallback/swipe, реальное снижение/рост/равенство цены,
отсутствие фиктивной скидки. PostgreSQL integration: атомарность, конкурентные
изменения цен, удаление обложки, стабильные image id, idempotent backfill.
Browser: RU/TJ, 375/768/1024/1440, корзина/quality, upload нескольких фото,
перестановка/удаление, price preview. Mutating UI tests разрешены только на localhost.
