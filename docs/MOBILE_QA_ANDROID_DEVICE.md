# Физический Android — чек-лист 0.4.0 (5)

Используйте выделенный Android с `arm64-v8a`. Standalone preview APK и SHA-256 указаны в [манифесте build 5](mobile-rc-20261118/artifacts.json). Preview с production-каталогом предназначен для просмотра и проверки обязательного входа. Для входа, checkout и tracking используйте отдельную тестовую сборку и изолированное окружение с тестовым OTP. Тестовая конфигурация с `127.0.0.1` на Android требует USB и `adb reverse` к порту собственного тестового API. Документ [MOBILE_TESTING](MOBILE_TESTING.md) описывает стенд.

## Установка и запуск

1. Включите USB debugging, подключите телефон, подтвердите доступ на его экране и запишите ID из `adb devices -l`. Проверьте SHA-256 файла командой `shasum -a 256 "$DF_APK"` и сертификат командой `apksigner verify --print-certs "$DF_APK"`.
2. Проверьте ABI командой `adb -s "$DF_ANDROID_DEVICE" shell getprop ro.product.cpu.abilist`. Установите `adb -s "$DF_ANDROID_DEVICE" install -r "$DF_APK"`. Если подпись ранее установленной программы отличается, используйте выделенный телефон или отдельную тестовую разновидность приложения. Сохраните пользовательские данные установленного приложения.
3. Проверьте версию через `adb -s "$DF_ANDROID_DEVICE" shell dumpsys package "$DF_ANDROID_APP_ID"`. Вызовите `adb -s "$DF_ANDROID_DEVICE" shell am force-stop "$DF_ANDROID_APP_ID"` и откройте иконку приложения. Повторите запуск после перезагрузки телефона. Metro для preview APK отсутствует.

## Сценарии на устройстве

- Главная, категории, поиск с системной клавиатурой, карточка, гостевая корзина после холодного старта, профиль, RU/TJ и сохранение выбора. Проверьте системный Back внутри модального экрана и в корне вкладки.
- На изолированном API выполните тестовый вход, остановку процесса, восстановление сессии, синхронизацию корзины с WEB, выход и повторный запуск. Сравните 1,5 кг и общую цену с WEB. На этапе checkout временно отключите доступ к тестовому API, верните связь и проверьте состояние корзины. Перед подтверждением прочитайте серверную сумму. Один запрос должен дать одну запись и один tracking.
- Снимите GPS-разрешение в системных настройках и проверьте повторный запрос, отказ, приблизительную и точную геолокацию. Для подписанного APK с настроенным Maps SDK проверьте тайлы, выбор точки, поиск и зону доставки по [карточке настройки карт](MOBILE_MAPS.md). Повторите ввод с поднятой клавиатурой и крупным системным шрифтом.

## Журнал дефекта

Укажите SHA, версию, package ID, модель, Android API, язык, время, сеть, шаги, фактический и ожидаемый результат. Снимите экран штатной записью. Для сбоя процесса сразу сохраните `adb -s "$DF_ANDROID_DEVICE" logcat -d -b crash -v threadtime > android-crash.txt`. Для живого процесса узнайте PID через `adb -s "$DF_ANDROID_DEVICE" shell pidof "$DF_ANDROID_APP_ID"` и приложите короткий фрагмент `adb -s "$DF_ANDROID_DEVICE" logcat -d --pid="$DF_ANDROID_PID" -v threadtime`. Уберите телефоны, OTP, токены, URL отслеживания, частные адреса и ключи перед передачей.
