## Что проверено в приложении

- Android API 36: холодный запуск процесса, каталог, фотографии, переходы,
  поиск с клавиатурой, карточка товара, корзина после перезапуска, профиль, RU/TJ.
  В фактическом DEX сохранены три открытых конструктора Room/WorkManager, R8
  включён. Карта без SDK key показывает ручной ввод адреса. Для функциональных
  тестов использован ATD, для снимков обычный Google APIs образ.
- iPhone 14 Simulator / iOS 27.0: публичные сценарии в Release. В отдельной
  сборке для тестового API проверены клавиатура и модальные окна телефона/OTP,
  сохранение аккаунта после остановки процесса, выход и гостевой профиль после
  повторного запуска. Apple Maps показала карту Душанбе. Выбор точки сохранил
  координаты внутри тестового полигона, а GPS-точка Simulator за его пределами
  блокировала доставку.
- Полный сценарий покупки: браузерная сессия подготовила корзину через штатные
  WEB endpoints. Ввод номера и OTP выполнен в мобильном интерфейсе. Приложение
  увидело позицию, изменение до 1,5 кг прочитано из WEB корзины. Доставка на
  тестовый адрес, выбор окна, серверный расчёт, подтверждение и tracking выполнены
  в iOS UI. Создан ровно один заказ. Администратор, сборщик и курьер обработали
  его через действующие ролевые API, браузерная админка показала заказ завершённым.
  Мобильный tracking показал «Курьер в пути» и «Доставлен». Фактический вес 1,48 кг,
  итог 21,80 сомони в общей системе. Payom adapter работал с loopback-шлюзом.
- Визуальное сравнение использует настоящие снимки сопоставимых размеров.
  Учитываются системные панели, состояния каталога и разница Apple Maps с WEB.
  Сравнили 11 публичных состояний для каждой платформы при ширине 390.
  Доля отличающихся пикселей iOS-корзины при одинаковой области снизилась с 31,0%
  до 18,2%. Совпадение всех экранов 1:1 остаётся открытым. На результат влияют
  шрифты платформ, фаза карусели, фокус клавиатуры, состояние модального окна и
  поставщик карты. Снимки тестовых аккаунтов, приватные логи и данные заказа
  хранятся отдельно от публичного набора.

## Установка на физический iPhone

1. Подключите iPhone к Mac с Xcode 27.1, включите Developer Mode и доверьте Mac
   на телефоне. В Apple Developer зарегистрируйте устройство для development
   provisioning и подтвердите доступность App ID. Для отдельного внутреннего
   тестирования можно использовать `tj.dushanbefresh.app.preview`, если ID
   зарегистрирован в нужной команде.
2. В локальном мобильном worktree установите зависимости с Node 22.23.3,
   pnpm 9.12.3, CocoaPods. Для отдельной установки с preview ID выполните:

   ```sh
   cd apps/mobile
   export EXPO_PUBLIC_APP_ENV=preview
   export EXPO_PUBLIC_API_URL=https://dushanbefresh.tj/api/v1
   export EXPO_PUBLIC_ASSET_URL=https://dushanbefresh.tj
   export EXPO_PUBLIC_ENABLE_ORDER_SUBMISSION=false
   export MOBILE_APPLICATION_ID=tj.dushanbefresh.app.preview
   corepack pnpm exec expo prebuild --platform ios --no-install
   cd ios
   pod install
   open DushanbeFresh.xcworkspace
   ```

3. В Xcode откройте **Signing & Capabilities**, выберите Apple Developer Team,
   поставьте **Automatically manage signing** и выберите подключённый iPhone.
   Сохраните настройки. Из того же терминала с preview окружением соберите
   `Release` для зарегистрированного iPhone. `DF_IPHONE_UDID` — ID устройства
   из окна Xcode **Devices and Simulators**.

   ```sh
   xcodebuild -workspace DushanbeFresh.xcworkspace -scheme DushanbeFresh \
     -configuration Release -destination "id=$DF_IPHONE_UDID" \
     -derivedDataPath /private/tmp/df-mobile-iphone-build build
   ```

   Установите подписанный `.app` из `Build/Products/Release-iphoneos` через
   окно Xcode **Devices and Simulators**. Вход в Apple Developer account и
   регистрация устройства выполняются в команде владельца приложения.
4. На телефоне проверьте запуск, каталог, фото, клавиатуру, жесты, RU/TJ и разрешение
   геолокации. Проверка покупки требует выделенного тестового API. В production
   профиле доступен публичный сценарий, создание заказов закрыто.

В локальном Keychain найдено 0 действующих code-signing identities. Скомпилированный
архив для `iphoneos` собран из production конфигурации. Для TestFlight нужен архив,
подписанный командой проекта, App Store Connect record и отдельное разрешение на
загрузку. Перерегистрировать существующий опубликованный ID не требуется.
[Подпись и установка Apple](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices).

## Что требуется для публикации

| Платформа | Действия владельца | Проверки после предоставления доступа |
| --- | --- | --- |
| Android | Подтвердить ID `tj.dushanbefresh.app`, дать доступ к Play Console и существующему upload key, подготовить Maps SDK key для правильного package + SHA-1 сертификата | Карта на подписанном APK, физический Android, подписанный AAB, Data Safety, контент и testing track |
| iOS | Указать Apple Developer Team, дать доступ к App Store Connect, development signing и тестовому iPhone | Подписанная установка, Keychain/GPS на устройстве, App Privacy, возрастная категория, export compliance и TestFlight |
| Обе | Указать серверное окружение для Geoapify и согласовать бюджет проверки, предоставить реквизиты издателя, контакты поддержки и правила хранения, утвердить release checkout и выполнение запросов удаления | Поиск/reverse по реальным адресам Душанбе, проверка delivery zone и карты, backend rollout, рабочая Privacy Policy и Account Deletion URL, тексты и снимки для магазина |

Geoapify key остаётся только внутри NestJS. Изолированные тесты проверяют API-контракт
и квоты. Реальные ответы Geoapify пока не проверены с нативного клиента. Для Android
нужен отдельный ограниченный SDK key для тестовой подписи, если тестируется preview.
Подпись из Play App Signing и upload key выполняют разные функции.
[Ограничения Google Maps ключей](https://developers.google.com/maps/api-security-best-practices).

По состоянию на 18 ноября 2026 сборка Android нацелена на API 36, а iOS-архив
использует iOS SDK 27.1. Android проверен на выравнивание 16 КБ. Для некоторых новых
персональных аккаунтов Google действует закрытый тест с 12 участниками в течение
14 дней. Соответствие требованиям удаления аккаунта требует фактического исполнения.
Текущая функция сохраняет запрос и отзывает сессии. Правила удаления/хранения и
публичные policy URL ещё должны быть подтверждены. Черновики RU/TJ, Data Safety,
App Privacy и metadata уже подготовлены в [MOBILE_STORE_MATERIALS_RU_TJ.md](MOBILE_STORE_MATERIALS_RU_TJ.md).
[Google target API](https://support.google.com/googleplay/android-developer/answer/11926878),
[Android 16 KB](https://developer.android.com/guide/practices/page-sizes),
[Play testing](https://support.google.com/googleplay/android-developer/answer/14151465),
[Apple SDK requirements](https://developer.apple.com/news/upcoming-requirements/),
[Apple account deletion](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion),
[Google account deletion](https://support.google.com/googleplay/android-developer/answer/13327111).

В черновике скриншотов четыре Android и четыре iOS экрана. Два Android кадра
сняты в 1080×1920, два — в 1170×2317 после обрезки только системных панелей.

Mac завершился таймаутом подключения. Причина на сервере не установлена.
Сценарий повторного захвата — `apps/mobile/qa/store-screens.yaml`.
[Форматы Apple](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications),
